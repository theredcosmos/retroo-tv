The pitch, in about a minute

Retroo TV is a time machine for music. You pick a decade and an old television tunes in: static, a rolling band, then a music video from that era, alternating two Bollywood songs with one Hollywood song. Listeners can share a YouTube Music playlist and it becomes a channel on everyone's wall. And you can start a jam: a room with a code where the host's TV drives everyone else's, with chat, an hour-long timer and open or private entry. The backend is Spring Boot with STOMP over WebSocket; the frontend is Angular with signals and no zone.js; the database is Oracle (H2 locally). The interesting engineering is keeping strangers' TVs in sync without accounts, and making a private room genuinely private.

One origin: nginx serves the app and proxies /api and /ws, so there's no CORS in production. Videos stream straight from YouTube to the browser.

1. Tuning in to a decade

  1. First tap. Browsers block sound until the user interacts, so the TV cues a song but waits for "Tune in", which calls play() synchronously inside the click.
  2. Pick a song. GET /api/songs/random?decade=90s&lang=hi&exclude=…. The client rotates hi, hi, en and sends the last 10 video ids so nothing repeats soon.
  3. Channel change. Static noise (canvas, 30 fps) and a short hiss (Web Audio) for at least 0.7 s, then loadVideoById. The snow stays until YouTube reports playing, which hides its loading screen.
  4. Song ends. A longer "signal loss" (2.2 s) and the next song. Unplayable videos are skipped, at most 5 in a row.
  5. During the song. 2–3 short interference bursts at random song positions, so pausing or seeking never mistimes them.

2. Sharing a playlist

sequenceDiagram
  participant U as Sharer
  participant A as API
  participant DB as Oracle
  participant O as Everyone else
  U->>A: POST /api/playlists {name, link, note}
  A->>A: rate limit (3 / 10 min / IP), parse list= id, normalise text
  A->>DB: insert (unique per playlist + name)
  A-->>U: 201 PlaylistResponse
  A--)O: after commit: /topic/playlists
  Note over O: appears in the spotlight next, with a highlight

The broadcast waits for the database commit (@TransactionalEventListener(AFTER_COMMIT)), so nobody sees a playlist that then fails to save.

3. Playing a shared playlist

  1. The IFrame API has no "list playlist" call, so the player cuePlaylists it and polls getPlaylist() for the video ids (8 s timeout → "private or empty").
  2. A play order is built: playlist order, or a Fisher–Yates shuffle where every song plays once per pass and a new pass never starts with the song that just ended.
  3. Titles arrive late (from getVideoData() once playing), so a jam host re-sends LOAD when the real title appears.

4. A jam: the host drives, guests follow

5. A private jam: ask to join

sequenceDiagram
  participant V as Visitor (code only)
  participant A as API
  participant H as Host
  V->>A: GET /api/jams/{code}
  A-->>V: locked snapshot (no chat, members, playback)
  V->>A: SUBSCRIBE /user/queue/jam-access, SEND request {name}
  A--)H: REQUESTS [{id, name}]
  H->>A: SEND admit {hostToken, requestId, allow: true}
  A--)V: APPROVED {pass, full snapshot}
  V->>A: SUBSCRIBE /topic/jam/{code} with jam-key: pass, SEND join {key}
  Note over V,A: With the invite link (/jam/CODE#k=secret) the visitor skips straight to the last step

The secret lives in the URL fragment, which browsers never send to a server. Rotating it kills old links; people already in keep their personal pass.

Deep dive

Staying in sync without accounts

The server is the clock

Every STATE carries updatedAt and every event carries serverTime. Guests compute offset = serverTime − Date.now(), so a phone whose clock is minutes off still lands within a second.

Correct only real drift

Expected position = positionSec + (now + offset − updatedAt) / 1000. Guests seek only beyond 2 s; smaller corrections would stutter.

Ordering

setPreserveReceiveOrder and setPreservePublishOrder keep each connection's frames in order, so SUBSCRIBE-then-join and STATE-then-CHAT arrive as sent.

Per-jam locking

Each JamSession synchronises its own state; two jams never contend. Broadcasting always happens after the lock is released.

Trust without logins

  • The host token is compared in constant time and never appears in a snapshot or event.
  • Chat authors come from the server's member registry, never from the message.
  • Clients may only SEND to /app/**; a direct SEND to /topic/… is rejected, so nobody can forge STATE or ENDED.
  • Private jams drop SUBSCRIBE frames without a valid jam-key header, by returning null from the interceptor. Throwing would send an ERROR frame and close the whole socket.

Self-annealing log

Problems we hit and how they were fixed

securityAnyone could broadcast fake jam events
CauseThe simple broker accepted client SEND frames to /topic/**, skipping every check.
FixAn inbound channel interceptor allows SEND only to /app/**.
securityRate limits could be dodged with one header
Causenginx appended the visitor's own X-Forwarded-For, and Spring used its first value as "the client".
FixCaddy replaces the header; nginx trusts it only from the private network and sends exactly one address.
performanceThe whole site felt sluggish
CauseA full-page film grain with mix-blend-mode: overlay sat above the video, forcing a re-blend every video frame; plus a never-ending scanline animation and 60 fps static.
FixPlain translucent grain (¼ the area), static scanlines, 30 fps static with the filter baked into pixels, lobby polling only while visible.
raceTwo quick clicks on mute left the TV muted
Causeplayer.isMuted() reports the iframe's state about 100 ms late, so both clicks read "unmuted".
FixOur own signals are the source of truth for mute and play intent.
UXThe seek bar jumped back while dragging
CauseThe 500 ms progress tick rewrote the input's value under the user's finger.
FixA dragging signal wins over the tick until change fires.
process"Backend tests pass" was false
CauseMaven was piped through tail, so the exit code checked was tail's. CI caught a stale test.
FixAlways read Maven's own exit code and sum the surefire reports.
toolingA regex silently lost \b
CauseAn edit script turned \b into a backspace character inside the jam-code parser.
FixRewrote it as (?![A-Za-z0-9]); unit tests now cover invite links.
robustnessKeyboard shortcuts crashed on some events
CauseEvents targeting document have no closest().
FixCheck e.target instanceof Element first.

Going live

Deploying

One Linux VM (4 GB RAM or more) with Docker, a domain pointing at it, and the production overlay. Full guide: docs/DEPLOYMENT.md.

cp .env.example .env # passwords, DOMAIN, ACME_EMAIL docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d --build

Why one VM

Jams and presence live in memory, so exactly one API instance; WebSockets stay open for hours; Oracle needs ~2 GB. Sleeping free tiers and serverless end jams.

What's exposed

Only Caddy (80/443, automatic HTTPS + HSTS). nginx, the API and Oracle are on Docker's private network; Swagger, H2 console and actuator aren't reachable.

Updating restarts the API, which ends live jams (they're in memory). Songs and shared playlists are in Oracle and survive.
